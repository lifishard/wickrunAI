# 主动管家：实现、权限与边界

本文记录 2.20.27 的实现范围，供使用者和维护者判断管家能依据什么提出建议，以及什么时候必须由人来决定。它与原有「找管家」的按次协作方案并存。

## 工作方式

1. 用户开启主动管家，选择同一账户下的常开桌面版作为执行电脑，指定模型、每日用量上限、时区和早晚简报时间。不开启时不运行后台采集或分析。
2. 应用内近期对话提供用户明确提出的需求。外部来源需同时满足全局开关、采集设备上的单独授权及域名或应用白名单。原始活动记录留在采集设备，最长保留 24 小时；撤销来源时删除该来源的本机记录及其派生共享记录。
3. 采集设备先将可见文字约束为有限片段，清除可识别的密钥、链接参数、邮箱和电话号码。选择「增强理解」时，脱敏片段会发送给所选模型提取主题与可能需求；选择「仅本机主题提取」则不为这一步发送片段。脱敏是尽力处理，所选模型仍可能收到未被识别的个人内容。共享管家记录只保存主题、意图、短摘要和证据引用，不同步原始活动。
4. 选定电脑按计划分析这些线索，提出候选目标，可检索公开资料生成早晚简报。用户可确认、纠正、否定目标，对简报和技能草案反馈。管家保留已审阅目标、否定反馈及其证据，使后续工作能沿用纠正而不把相似的错误推测反复提出。技能草案必须审阅，加入技能库时默认停用。来源、模型请求、研究步骤与控制动作显示在活动记录中。
5. 开启管家时「日常自动执行」默认选中，可在启用前或之后关闭。开启后，合适的候选目标可进入独立 Work 会话，先在隔离工作区制作可审阅的文件、草稿或原型，再由用户决定是否采用。单个目标只自动派发一次；同一时刻只运行一个，且受每日自动 Work 次数上限约束。关闭日常自动执行时，用户仍可手动将已确认或纠正的目标交给 Work。

手机可以查看同步结果、补充需求和排队工作，也可在本机授权范围内提取活动摘要；定时分析、研究、简报和自动 Work 派发只由选定桌面版运行。Work 会话使用现有模型路由与续跑检查点；移动端需要本机工具时仍依赖电脑中继。各采集设备可能各自调用所选模型提取摘要，所以管家认知的每日用量上限按设备记录，不能当作跨设备账户总限额，也不是普通 Work 会话的总额度。自动 Work 另受每日次数上限约束，其模型用量按普通 Work 任务计算。电脑离线时主动管家任务等待它恢复。现有 API 密钥加密同步机制保持原样；这并不意味着发给所选模型的脱敏片段仍只留在设备上。

## 来源实际能看到什么

| 来源 | 实现范围 | 需要的授权或限制 |
| --- | --- | --- |
| wickrunAI 对话 | 近期用户主动发出的内容，经短摘要处理 | 管家总开关及应用内来源开关 |
| 桌面浏览器 | 本地扩展在精确允许的 HTTPS 域名，读取当前视口可见的正文文字；单页应用内容变化后重新检查 | 安装扩展、域名白名单、设备授权；登录、私信、支付等路径排除 |
| Windows 应用 | 白名单前台窗口暴露给 UI Automation 的静态文字 | 设备授权、进程白名单；应用不开放文字时无法读取 |
| macOS 应用 | 白名单前台应用暴露给辅助功能的静态文字 | 系统辅助功能权限、应用白名单 |
| Linux 应用 | X11 白名单前台窗口标题 | Wayland 不支持；不声称读取窗口正文 |
| Android 预览客户端 | 经系统授权的可访问性文字与用户主动分享的链接 | 受 Android 权限、目标应用和设备实现限制，需真机验收 |
| 主动分享链接 | 用户提交公开 HTTPS URL 的域名与路径主题 | 不抓取正文、图片或视频；查询参数、登录及私密路径拒绝 |

目前没有可用的通用第三方应用采集连接器。没有屏幕截图/OCR、视频帧或音频识别，也不能读取 Instagram 收藏、转发或 Reels 历史。看到一个主题只能作为接触线索，不能证明喜欢、收藏、购买意图或真实需求。

## 隐私规则与旧线索

浏览器和桌面的白名单与拒绝名单同时生效，拒绝规则优先，桌面采集在读取文字前检查；登录、支付等身份验证内容始终丢弃。每台设备单独保存隐私规则：用户填入的排除词使匹配片段直接丢弃；仅加密保留词允许片段留在设备的加密本机存储，但永不交给模型。默认对联系人及财务字段做脱敏，健康类别默认排除。桌面原始事件使用操作系统安全存储加密；Linux 如只能提供 `basic_text` 等不安全后端，就拒绝落盘，不退回明文。Android 使用系统 Keystore 保存本机采集数据。

保存隐私规则会停止正在运行的管家 Work，清理旧脑记录中不应保留的线索，并在共享线索再次进入模型前重查规则。规则按设备保存，跨设备使用者需要分别设置。已经发给模型的旧请求无法撤回；清理针对本机及同步中的后续使用。

Android 设置中可以查看系统是否已允许忽略电池优化，并打开系统授权页面。应用不会绕过系统限制，是否放行需要用户在设备上确认；后台存活和无障碍采集仍需真机验证。桌面版隐藏窗口后继续运行，但电脑休眠或离线时不会由云端接替执行。

## 执行边界

管家的后台认知运行器只接收文本分析与公开网页研究任务，不授予文件修改、命令执行、发消息、账户操作、谈判或金融交易权限。模型提出的目标不等于用户确认；研究结论与链接需由用户核实。

日常自动执行是单独开启的有限授权。自动 Work 必须有独立工作区，API 模型只获得工作区内的文件读取、写入、文档生成与核验工具；不继承普通会话已开启的命令、浏览器、MCP、代理、删除、发布或外部发送能力。它可根据未确认的候选目标制作可撤销的草稿，但不能把推测当成用户的最终决定。已否定的目标不能执行。用户主动发起的 Work 使用原有工具与审批规则。自动 Work 的文件操作事后留痕供审阅；在完整版本已保存时，文本文件可逐行查看并回退，DOCX/PDF/XLSX 等二进制文件保留完整字节供哈希核验和回退，但无法逐行预览。超过 16 MB 的单文件或不安全的链接文件不会生成可回退版本，界面应显示未保存版本的提示；独立工作区仍保留原目录不受修改。

订阅客户端另有宿主边界：Codex 使用仅能写入独立工作区、禁止联网的沙箱，关闭命令、浏览器、MCP 和代理工具，额外授权请求一律拒绝；Kimi 与 Grok 的 ACP 操作只自动放行能核实路径且位于独立工作区内的文件编辑，终端、网页读取与未知操作均拒绝。ACP 当前没有可核实的操作系统级沙箱，此边界依赖客户端把操作提交给宿主审批，不能声称和 Codex 沙箱同等级隔离。当前 Claude Code 桥接无法证明同等文件/命令隔离，因此自动任务只生成无工具的只读草稿，并明确说明没有生成文件。文件操作不能代替账户授权。代码保留针对金融/谈判动作的精确授权数据结构，但此版管家没有实现这些执行动作，因此不能把它描述成「获授权即可自动交易」。暂停会阻止后续采集与模型派发，并取消本机运行中的管家请求；跨设备状态以账户同步为准。

Work 的文档读取支持 PDF、DOCX、XLSX、XLSM、XLS、PPTX 与 POTX 的可解析文字和表格。旧 `.ppt` 文件需先转换，扫描版 PDF 的图片文字需另行 OCR；没有可提取文字时不能声称已经理解附件内容。

## 同类产品基线（核对于 2026-09-30）

这几个官方说明定义了要比较的能力，不代表本项目已具备同等范围：

| 产品 | 官方公开能力 | 本版差异 |
| --- | --- | --- |
| [Grok Bot](https://docs.x.ai/grok-bot/overview)、[移动端](https://docs.x.ai/grok-bot/mobile) | Bot 使用持久云电脑，桌面与手机共享 Bot、会话、例程和连接器；电脑关闭后云端仍工作 | wickrunAI 依赖用户选定的常开电脑，手机通过同账户查看与提交；没有通用云电脑 |
| [Claude Cowork](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)、[定时任务](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork) | 云端会话与日程可在电脑离线时继续；需要本机文件或应用时通过打开的桌面版访问 | wickrunAI 的持续分析与简报只在所选桌面版运行，来源范围更窄；没有 Cowork 的跨应用执行 |
| [ChatGPT dots](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)、[Work 定时任务](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex) | dot 可主动查看已连接信息、形成记忆并在云电脑持续工作；Work 可按日程或受支持事件运行任务，重要操作受权限与批准控制 | wickrunAI 提供本机授权来源与证据化需求推测，但没有 dot 的云电脑、广泛连接器或事件触发工作流 |

后续若扩展连接器、视觉/视频理解或可执行动作，应单独设计授权、数据保留与验收；不能用模型提示词代替平台权限和可验证的行为边界。
