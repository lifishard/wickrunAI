- **429 问题已定位并修复**：协作空间原本就复用单一 Agent 的 runAgent、全局自动重试设置和默认 62 秒退避；Retry-After 优先，等待受恢复时限、运行预算与取消约束。上轮 OpenRouter 曾自动倒计时，随后由主负责人手动暂停；SenseNova 的 TPM/RPM 原文夹带 insufficient_quota，被共享分类器优先误判为不可重试额度耗尽。现明确分钟限流优先于通用额度代码；402、明确余额耗尽、裸 insufficient_quota 和非分钟日额度仍不自动重试，401/403 维持鉴权优先。
- **真实桌面退避已通过**：本机合成服务返回同类 SenseNova 429 原文，应用显示“62 秒后继续”，实际两次 HTTP 请求相隔 62144 ms，同一路由 429 → 200；没有手动重发或换模型。交付经界面批准 completed，已知夹具用量 200 tokens，首个失败请求用量仍为缺失。这不能证明真实 SenseNova 当时等待后必然可用；旧报告的 quota 分类保留为历史证据。
- **U1 文本快速准备已落地**：任务页选择接入、模型与直接完成/讨论后完成/完成后复核。准备普通成员与可编辑流程，并保存固定版本，下一步确认才派发。空团队实测无需进入成员页或设计器：保存任务 → 准备并检查 → 确认开始 → 验收。准备后 1 成员/1 流程/1 版本，运行和请求数仍为 0。
- **定制与边界**：高级设置保留原有成员、文件流程、已有流程选择及设计器；已有负责人/已有流程不被快速准备覆盖。新快速成员仅处理文本、关闭自动接力、不开放文件/命令，遵守项目允许接入与预算。文件任务首跑、分别选角色模型、团队预设、运行页信息层次和真正的新手对照仍未完成。

## 实施原则

- 主执行器、存储、工具与 UI 的现有路径优先，不引入第二套运行引擎或数据库。
- Agent 在独立目录工作；主负责人核对差异并整合。子任务完成声明不等于验收。
- 程序测试、受控传输测试、真实桌面操作、真实供应商试验分开记录。
- 不自动发布、安装替换日常应用或使用生产项目文件做故障注入。
- 系统沙箱扩展、供应商原生压缩、大规模自动路由、自动经验采用属于条件中的后续决策项：先记录能力边界和对照证据，不凭一轮成功启用。
