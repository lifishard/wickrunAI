# 协作空间会议室

会议的目的是共同理解问题、发现盲点、改进方案、明确决定与下一步。贡献的价值不按消息数量、辩论胜负或是否赞同主持人衡量。

## 使用流程

1. 在协作空间的「会议室」新建议题，写下期望的结果、背景材料和约束，选择 Claude Desktop、ChatGPT 参会。用户始终是主持人和决策者。
2. 用户可以从明确议题、各自观点、交流与澄清、归纳分歧、请你决定几个阶段中选择适合当前讨论的阶段。允许回到前面的阶段。切换阶段撤回旧邀请，以免旧背景下的答复被当作当前答复。
3. 可以手动指定成员与发言重点，也可以选择「自动轮流讨论」，设置共同讨论重点及每位成员 1–5 次发言。开始自动轮流后，在每个客户端各发送一次加入指令；成员通过 `wickrun_meeting_wait` 加入并保持接收邀请。双方都加入后，会议室自动安排交替发言，不再需要每轮复制邀请。
4. 成员先阅读材料及共享记录，再贡献观点、问题、异议、回应、改进建议、归纳草案，或明确暂无补充。界面显示该贡献基于哪一条记录之前的信息，不把传输完成描述为认同或已经理解。
5. 需要用户拍板时，成员通过专门的提问工具给出问题、原因、选项及影响、建议。问题出现在发言区，同时提醒用户。用户可自由填写答复，或说明原因暂缓；不设预选提交，不以超时或沉默当同意。
6. 等待用户决定时，依赖该决定的发言停止。自动轮流会等待答复，用户回答后安排下一位成员重新读取记录并继续。用户暂缓、改变阶段或暂停时停止本轮；要讨论独立事项，可以暂停自动轮流后明确邀请。暂缓保留未决状态，不可作为已回答的决定依赖。
7. 用户整理并确认最新记录对应的纪要：共识与依据、分歧、待验证或暂缓问题、行动建议。新发言会使已确认的旧纪要变为待复核。结束会议前需确认当前纪要，且不存在未处理的用户问题。
8. 会议记录可导出为 Markdown；确认后的纪要可整理为一个任务草稿。任务仍需填写验收要求、选择执行方式和独立质检，不自动派发。

## 建设性讨论约定

- 先理解再评价；异议针对观点、依据和方案，不针对成员。
- 明确区分事实、推测、偏好和未核实信息，提出可验证的办法。
- 鼓励修正立场、接受补充；没有新信息可以跳过。
- 保留异议，不强制一致，不把未发言或未反对当作同意。
- 公开交流结论、简要理由和依据，不要求输出私密思维链。
- 重复争论由主持人归纳为待验证问题或提交用户决定；本版主持人为用户，不宣称已有自动主持人。
- 会议纪要、建议以及用户在会议中的取舍，不会写入工作流质检结论，也不等于文件修改或外部动作授权。

## 真实客户端接入

Claude Desktop 复用现有本地 `wickrun_ai` 扩展。应用更新后扩展加载应用维护的 MCP 脚本；可重新安装扩展以刷新可见工具。模型在 Claude Desktop 中选择。

ChatGPT 入口生成本机 stdio 连接配置，仅暴露五个会议工具。它不是模型 API 路由，也不是 Codex。配置中的本机路径用于隧道运行器，不能直接当成网址粘贴到 ChatGPT。

按 [OpenAI Secure MCP Tunnel 文档](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) 在本机运行隧道并连接 ChatGPT 开发者模式。隧道需要相应 Platform 权限、运行密钥及 ChatGPT 开发者模式权限。也可以另行部署符合官方要求的 HTTPS MCP 接入，但本版不自动开放公网端口或部署服务。

[官方插件快速入门](https://developers.openai.com/plugins/quickstart)明确演示 ChatGPT Work 网页会话。普通 Chat 模式、用户指定模型及桌面版本是否支持，需要在用户账户中实测，不能用 Work、Codex 或 API 回答冒充普通 Chat。此版本不提供自动控制 ChatGPT 聊天窗口的功能。

自动邀请使用 MCP 长等待：客户端加入后，服务端在轮到该成员时返回邀请，成员读取最新记录并提交一次贡献，然后继续等待。它能自动协调保持参会的会话，不能唤醒已停止或关闭的聊天。首次加入或断线后仍需在对应客户端继续会话。普通 Chat 会话是否支持这些工具仍需账户实测。

每次工具等待最多 25 秒，连续八次等待没有新发言或用户答复时自动暂停（约三分钟，另加客户端响应时间）；客户端退出或遇到权限确认时也可能导致暂停。返回 `stopped` 后必须停止。你可以处理问题后重新开始，让双方重新加入。应用重启不恢复自动轮次，不重复发送未确认贡献。成员都表示暂无补充时提前结束本轮，不把它视为一致同意。

## 存储与权限

- 独立主进程存储 `meetings-v1.json`，原子写入、前一版备份；重启后保留发言、邀请、提问、用户决定和纪要。记录目前仅在本机，不参与云同步或现有完整备份包；请使用会议导出保留可读记录。
- 每个会议显式选择可见的客户端；桥接令牌决定发言身份，模型不能通过参数冒充用户或另一成员。连接授权代表客户端来源，不认证客户端实际选择的模型名称。
- 每次邀请只提交一次；重复同内容返回原结果，冲突内容拒绝。撤回、改阶段或结束后拒绝迟到发言。记录只追加，修正观点通过新发言表达。
- 外部客户端只能列出/读取受邀会议、提交本次贡献、向用户提问。没有用户答复、确认纪要、切换阶段、执行任务或质检批准工具。
- 每场最多 30 次 AI 贡献、常规发言最多 500 条记录；达到记录上限仍允许用户回答和结束会议。自动轮流有用户指定次数及等待次数上限，不自动重发模型请求。界面三秒刷新仅读取本地会议记录。
- 客户端配置文件含本机秘密连接令牌，不应上传共享；界面只显示命令和路径。

## 验证边界

测试覆盖客户端来源隔离、实际 stdio MCP 通信、加入一次后的自动轮流、提问暂停与答复后恢复、有限等待与停止、引用与回应、重复及迟到提交、阶段变化、用户提问/回答/暂缓、独立事项继续、最新纪要检查、重启恢复和质检记录不被改写。

离线测试里的 Claude、ChatGPT 是独立 MCP 协议测试客户端，没有调用真实模型或用户账号。因此不能用这些测试声称 ChatGPT 普通聊天接入已经实测通过，也不能声称真实模型始终会建设性发言。
