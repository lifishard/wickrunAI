# Mobile capability audit — 2026-09-27

Baseline: desktop `bebc897` (2.20.8), web `debe687` (2.20.7). Source review on Windows; no physical-device acceptance test was performed. The web `node_modules` junction was not modified. Line references below describe the baseline before release preparation changes.

| Capability | Electron desktop | Hosted web on phone/iPad | Baseline Capacitor bundle from desktop |
| --- | --- | --- | --- |
| Chat, models, settings, skills | Shared React UI, native HTTP | Shared UI with server proxy | Shared UI; Android HTTP code has a streaming defect; no iOS HTTP implementation |
| Google account and sync | Device-code flow in system browser; encrypted bearer credential; separate account directories | Same-origin Google OAuth cookie session; account-scoped browser storage | No native account bridge; falls through to relative localhost API URLs |
| Ordinary document input | Native picker and permitted files | Browser file picker, 12 MiB chat attachment batch | Picker disabled when `desktop()` is null; media-only HTML picker still exists |
| Artifact preview/edit/save | Native file reads, revision checks and desktop document tools | IndexedDB workspace; browser import/download and basic document editing | Desktop path-based file cards cannot read remote/local binary files; no native Files/share adapter |
| Returned task files | Verified transfer, 100 MiB per file, 500 MiB/50 files per task | Cloud relay receiver and IndexedDB workspace support the same returned files | Does not include the web cloud relay/artifact receiver |
| Shell, Chrome control, installed AI CLIs, stdio MCP | Host capabilities | Hosted relay can ask a connected desktop/CLI to work | No local host capabilities; manual remote bridge only |
| Scheduled/background work | Renderer scheduler while app is running; desktop notification bridge | JavaScript timer while page can run | JavaScript timer; no reliable suspended/background scheduling or native notifications |
| iPad layout | Desktop layout | Responsive web layout | Existing 860 px breakpoint, partial safe-area padding; unverified keyboard, split-screen and rotation |

## Prioritized findings and minimum fixes

1. **Android streaming request fails before receiving SSE.** `native/android/SncHttpPlugin.java:76` enables chunked *request* encoding, then line 82 enables fixed-length request encoding. These modes are mutually exclusive. Remove the chunked setting; a fixed-size JSON request can receive a streamed response. [Android API contract](https://developer.android.com/reference/java/net/HttpURLConnection#setFixedLengthStreamingMode(int)).
2. **Generated Android plugin package is inconsistent.** `scripts/install-android-plugin.mjs:15` and `native/android/SncHttpPlugin.java:1` use `cn.sensenova.chat`; `capacitor.config.ts:4` uses `dev.anyai.app`. Derive the generated Java namespace from the one selected application ID and patch/register without discarding unrelated MainActivity code.
3. **iOS selects a plugin it does not have.** `src/lib/transport.ts:873` chooses Capacitor for any native platform; `:515` immediately subscribes to `SncHttp`, which only exists for Android. This preparation adds iOS templates, but they must be compiled into the App target and registered before runtime verification.
4. **Native cloud accounts are not implemented.** `src/lib/cloud-api.ts:13` recognizes only `window.snc`, otherwise line 27 uses relative `/api/cloud/*` with same-origin cookies. `src/components/CloudSyncControl.tsx:152` links to `/api/auth/google`. These resolve against the native bundle origin, not the cloud service. Implement a native system-browser authorization flow and account-scoped data/Keychain token storage before advertising mobile sync. Do not merely replace the API URL: cookie origin checks, OAuth return handling and local account isolation also need adaptation.
5. **Native API keys use ordinary Preferences.** `src/lib/transport.ts:635`–643 reads/writes `secret:*` through Preferences. Migrate to platform secure storage, delete the old plaintext only after a verified secure write, and fail visibly when secure storage is unavailable. The iOS template uses Keychain; Android needs its Keystore-backed implementation. [Preferences uses UserDefaults/SharedPreferences](https://capacitorjs.com/docs/v7/apis/preferences), and its iOS use requires the UserDefaults privacy-manifest reason (recommended `CA92.1`).
6. **Document input/output needs an explicit mobile adapter.** Desktop `src/App.tsx:735` rejects a non-Electron picker and `:1890` disables it; `src/components/ArtifactPanel.tsx:132`–135 rejects path-based file reads without desktop. The web repository has reusable `pickBrowserAttachments` (`src/App.tsx:718`), `src/lib/browser-artifacts.ts`, and `src/components/WebArtifactPanel.tsx`. Reuse these intentionally and add native Files/share export; a Blob-download click must be verified on iOS/Android. Keep task artifact quotas separate from chat/media attachment limits (12 MiB media, differing chat budgets).
7. **Remote tools are not native mobile tools.** `src/lib/transport.ts:304` uses browser `fetch` to a configured desktop URL; `electron/remote-server.cjs:253` exposes HTTP URLs. `capacitor.config.ts:8` disallows mixed content and line 11 uses HTTPS locally, so the documented HTTP pairing path is blocked by the native WebView security policy. Prefer a verified secure transport/relay; do not broadly disable TLS or ATS. File results also need byte transfer, not just desktop filesystem paths.
8. **Background execution must be described and tested honestly.** `src/App.tsx:1747` is a 20-second JavaScript timer. Team runtime and notifications at `:268`, `:492`–493 require Electron. Persist run state and show interruption/reconnect behavior; do not claim that phone locking or app suspension keeps the agent/scheduler running. [Apple background execution guidance](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time).
9. **iPad/safe-area acceptance remains open.** Desktop `src/styles.css:1135` changes to drawer navigation only at 860 px. Top safe-area padding is within that narrow rule; bottom padding exists at `:306`; landscape left/right insets and software-keyboard viewport behavior are not handled comprehensively. Web has `100dvh` in `src/web/web.css:8`, but later topbar padding overrides safe-area padding. The existing web test checks only a 390×844 Chromium viewport (`tests/cloud-browser.cjs:69`), not iPad/WKWebView/real devices. Add iPad portrait/landscape, split-screen, keyboard-open and file-picker acceptance cases.

## Account implementation is not interchangeable

Desktop `electron/cloud-account.cjs:6` trusts the fixed Railway origin. Lines 65–85 perform a browser device-code flow with a verifier and encrypt the bearer token using Electron safeStorage; the token stays out of the renderer. Web `src/web/WebRoot.tsx:20` fetches the hosted session before rendering, then sets an account scope. `src/web/session.ts:4` names storage by Google user ID; `src/lib/transport.ts:738`–751 scopes normal storage and sessionStorage model keys. The Capacitor Preferences implementation has no corresponding account prefix/switch. Packaging the web repository's `dist` locally is also insufficient: WebRoot's initial relative session fetch would prevent startup.

## Minimum physical-device acceptance

Check one iPhone, one iPad and one Android device: fresh install/upgrade, safe areas and keyboard, Chinese/emoji streaming across network changes, stop/timeout/HTTP errors, key save/relaunch/delete/lock behavior, OAuth return and two-account isolation when implemented, Files/photo input, receiving and exporting a verified artifact, and interruption/recovery after suspension. Check the 100 MiB file and 500 MiB/50-file task boundaries separately from small chat attachments. Simulator or desktop browser results must remain labeled as such.
