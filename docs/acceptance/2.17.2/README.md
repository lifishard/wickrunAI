日期：2026-09-20（America/Vancouver）。代码基线 cf70b1b / 2.16.2，当前工作树版本 2.17.2。未提交、打包、发布或替换日常安装。

## 实际操作范围

主负责人使用 Windows 原生界面工具操作标题为 `wickrunAI · 2.17.2 文本与记忆验收` 的独立 Electron 窗口。实例使用独立数据目录、合成项目、本机 HTTP 受控响应；没有使用用户业务文件或真实供应商服务。OpenAI、日常 wickrunAI 和之前验收窗口均保留。

1. 进入协作空间，从任务页点击“生成文本复核流程”。确认独立成员与“文本答复”范围，保存版本。
2. 第一次运行因默认流程 30 分钟超过夹具项目 10 分钟而被正确拦截，未发送模型请求。界面改为 10 分钟后保存 v2；产品生成入口同时补上按项目上限收敛预算。
3. 从应用启动 v2。初稿没有“待核实”，独立复核返回 fail；执行成员返工，当前新快照引用核对后 pass。
4. 展开“本次记忆选择”，确认 2 条、173 / 6000 字符；其余冻结已采用记忆显示不匹配、过期、超限原因。候选记忆不进入运行快照。
5. 核对交付后通过界面“批准”。任务状态 completed，保留第一次 fail 和第二次 pass 及用户批准事件。
6. 用界面刷新加载最终构建，确认 completed、用量和记忆选择仍在。此步骤是渲染器重载，不宣称 OS 进程重启。
7. 在项目记忆修订任务关键词为“发布,验收”，保存为候选 v2。已完成运行仍冻结采用的 v1，仅含“发布”，未被后续编辑改写。
8. 在最终构建中再次从任务页生成文本复核流程，界面自动显示 10 分钟；持久记录确认不超过项目 token/时间上限。

## 自动化覆盖与限制

文本复核测试覆盖 SHA-256/attempt/版本、旧快照、伪引用、漏引输入、空输入、超限拒绝、文件变更不能冒充文本，以及真实运行引擎和持久存储的 fail→返工→pass→用户批准。

记忆测试覆盖旧记录兼容、类型和范围校验、过期边界、中文子串与英文词边界匹配、整条超限略过、不可变快照、项目隔离、运行注入及后续修订不改旧运行。

用量测试覆盖两路由守恒、pending/final 及续跑去重、200 条事件裁剪之外的汇总、未分配身份、新旧请求混合缺口、旧讨论记录归属和隐私导出。混合旧请求不会被当成完整成本；共享任务结果不等于各路由的因果贡献。

受控模型只证明工程闭环，不能证明真实模型会发现所有缺陷、记忆语义相关、压缩语义保真或协作节省成本。此前两条 500/402 来自误选的付费路由，不证明整个网关不可用；用户指定免费路由的真实策略与长任务试验尚待完成；本批未再次消耗请求、购买额度或修改沙箱。
