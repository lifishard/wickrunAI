## 429 结论

协作空间使用同一 runAgent，并传入 settings.autoRetry；可重试的临时限流默认等 62 秒，优先采用 Retry-After，受恢复时限、预算和取消约束。上次 OpenRouter 已进入重试，后经界面手动暂停。SenseNova 的 `inference exceeds tpm/rpm limit (code insufficient_quota)` 因共享分类器先匹配 insufficient 而被判 quota，确实跳过了自动退避。

现按明确分钟窗口信号分类。HTTP 429 和无状态 SSE 均覆盖；裸 insufficient_quota、日额度耗尽、402/余额问题保持不可重试，鉴权优先。修复不是为协作空间另造退避器。

实际桌面运行 `teamrun-136e3148-84d2-49a1-9d2a-b66d7ffa90ad`：

1. 从空团队界面新建任务，填写目标和验收标准。
2. 在任务页选用本机合成模型、默认直接完成；“准备并检查”创建 1 成员、1 流程、1 版本，此刻 0 运行、0 模型请求。
3. 确认范围并开始。首次 POST 返回上述同类 429 原文，界面显示 62 秒倒计时。
4. 未手动暂停或重发；第二次 POST 在 **62144 ms** 后使用同一模型返回 200，生成“协作易用性验收成功。”。
5. 交付仍等待人工批准；通过按钮批准后 completed。

200 是成功请求的夹具报告用量，失败请求用量缺失；不代表外部供应商费用。此测试完整经过实际 Electron 界面、runAgent、传输和本机 HTTP，使用真实等待时间。真实 SenseNova 服务退避后的任务产物仍未验收。
