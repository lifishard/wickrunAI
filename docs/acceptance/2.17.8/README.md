# 2.17.8 角色定制与团队方案验收

Git 基线仍为 `74cab88 / 2.17.5`，在已有未提交的 2.17.6、2.17.7 上继续实现。交付源码 **2.17.8**；未提交、打包、替换安装版、同步 GitHub 或发布。本次开发和独立应用验证不需要用户先打包。

## 实现范围

U2 的新文本任务配置：准备页默认保持简单入口，按需展开“分别设置助手与职责”，分别配置执行/讨论/复核或方向探索/方案整理。可选择不同接入和模型、编辑职责、从已有 API 成员复制配置。实际角色列表与同一份生成图预览保持一致；查看具体步骤可看到模型、职责和工具说明。

复制只带入模型与职责，创建当前任务的新成员。思考强度使用 `medium`，成员默认 30,000 tokens / 20 分钟，并收敛到项目上限。不会隐式继承来源的预算、思考强度、工具、技能或自动换路由，原成员与旧运行不改写。原成员失效、停用、非 API 或不在允许接入中时拒绝复制。

团队方案保存在当前项目，包含工作方式及展开后的角色模型/职责，不保存任务目标、验收内容、凭据或权限字段，也不保留对来源成员的动态引用。载入后仍需准备和确认开始；另存需新名称，同名（去首尾空白且忽略大小写）拒绝，最多 20 份。名称最多 80 字符、模型名最多 200、职责最多 12,000；无效输入整体拒绝。删除只删除保存方案，当前配置与已有任务保留。

## 实际应用验证

Browser 技能未提供，使用已有 Playwright 的 Electron 接口，启动仓库实际 Electron 主进程与最终生产构建。独立 userData、本机合成 HTTP；初始只种入两项空任务与两名已有成员。之后配置、保存、启动、验收、另存、删除均通过实际产品界面，没有调用隐藏状态接口推进任务。未访问外部模型、使用日常凭据、修改日常用户目录或操作 OpenAI 窗口。

测试路径：任务页 → 选择“完成后独立复核” → 复制两名已有成员 → 分别编辑模型/职责 → 保存团队方案 → 刷新并载入 → 修改统一模型并单独恢复复核模型 → 准备并查看实际步骤 → 确认开始 → 复核与人工验收 → 第二任务复用、另存和删除 → 独立进程重启。

| 检查 | 实际结果 |
|---|---|
| 页面身份、内容、异常层及日志 | 加载实际 `dist/index.html`，wickrunAI 标题；非空，无页面异常及相关控制台错误 |

| 独立进程重启 | 保存方案、已准备下一任务、旧完成运行保留；没有重发请求 |

最终独立项目为 2 任务、6 成员（2 原始 + 4 新建）、2 工作流、1 已完成运行、1 保存方案。两次合成回复共报告 **600 tokens**；这是夹具数据，不是供应商费用或质量证明。通用澄清工具仍由基础引擎提供，“无额外工具”不代表所有内部交互机制都被禁用。
