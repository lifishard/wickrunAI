# 新会话与并行任务协调

输入 `新开一个 Work，帮我检查这个项目` 或 `/work 检查这个项目`，会创建应用内的独立会话并开始任务。输入 `开新对话`、`/chat` 或 `/work` 则留下空白会话。新会话继承来源的模型、凭据和项目，仅携带这次任务说明，不复制历史消息、执行现场或压缩记录。没有有效凭据时保留任务草稿，配置后可继续发送。

支持工具调用的 API 模型还可使用 `create_conversation` 创建会话，以及 `coordinate_tasks` 查看同项目或同组的任务状态、发送协调消息。创建请求和消息都使用稳定请求键去重。模型发起的新任务在后台运行，用户自己的新建指令切换到新会话。新任务的凭据和模式独立解析，不跟随当前窗口切换。

“并行任务”入口提供状态、最近进度、接收方选择和协调消息。消息持久保存，在接收方下一次请求模型时加入上下文；API 与本机 CLI 会在下一轮读取，MCP Bridge 会在下次创建交接任务时带入。已经交给外部 Claude 的请求不会被中途改写，暂停或完成的任务不会自动重新启动。该消息是协作材料，不授予额外目录权限。API 模型可主动协调；本机 CLI 和 Claude Desktop 尚未提供这两个应用管理工具，可用直接输入指令及协调面板。

## 与工作流一致的文件隔离

桌面端通过以上指令创建 Work 时，复用工作流的文件副本、哈希差异检查和合并机制。默认复制来源会话的原目录，否则复制第一个已授权目录；API 工具可显式选择另一个已授权目录。各 Work 在不同副本运行。原目录保持不变，只有用户在“并行任务”中检查并应用文件差异时才合并。若原文件被其他任务修改，合并会被阻止；中断合并沿用已有恢复机制。

副本准备失败时会保留会话并显示原因，不降级到原目录执行。撤销原目录授权后，副本文件工具也停止执行。应用改动后的副本不再继续写入，请创建新的 Work。旧会话仍遵守共享目录占用与排队规则。

副本沿用工作流的 128 MB / 10000 文件上限，排除 `.git`、`node_modules`、`.next`、`dist`、`build`，拒绝符号链接；大型项目应选择较小的授权目录。这个上限针对工作区快照，与成果上传的单文件 100 MB 限制不同。文件工具限定于副本，命令和官方 CLI 的工作目录也指向副本；这不是操作系统级沙箱，任意脚本或外部客户端仍需遵守其自身的权限控制。

网页版同步新会话、自动开始和协调界面；浏览器不会获得本机目录访问权限，也不会假设远程 Claude 沙箱与本机文件是同一个工作区。云端中继仍由现有连接器负责，网页中新建 Work 不为远端额外授予本机文件权限。

## 验证

回归覆盖指令解析、空白与自动开始、请求去重、独立上下文、项目范围、协调消息读取、Chat 中应用工具调用，以及双副本写入、冲突合并、撤销授权与伪造会话绑定拒绝。界面验收另用独立测试用户数据运行网页和 Electron，避免改动真实历史与工作文件。
