# wickrunAI 2.20.24：请求格式检测撞上限流也会等待重试

## Fixed
- 第一次用某个模型（例如 deepseek-flash）时，会先发几条很短的请求检测它接受哪种请求格式。检测时撞上 TPM/RPM 限流，原来直接停下并报“兼容性检测暂未完成（HTTP 429）”，不走退避。现在检测和正式请求一样：等调用额度恢复后重新检测，再继续任务；等待时间超过本阶段自动等待上限才停下。已经检测过的模型（例如 kimi-k3）不受影响，所以之前只有新模型会出现这个问题。
- 因限流没做完的检测结果不再存下来。原来这份未完成的结果会缓存 5 分钟，期间每次运行都直接报同一个错，不再联系上游。
