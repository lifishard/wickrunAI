# wickrunAI 2.20.21 — 运行中调高上限，从停下的地方接着跑

运行因为次数或用量上限停下时，可以在运行页直接调高上限并从检查点接着跑，不用再新建运行从头跑。设计器里已经改高的上限一键带入。长的上游产出和讨论改为按文档分段读取。

## Added
- 上限卡片：列出卡住运行的上限（某一步最多执行几次、返工连线最多往返几次、成员每步 tokens、本次运行总 tokens / 步数 / 分钟），显示已用和上限；流程设计或成员设置里已经改高的值直接带入，也可以手动填写。点“提高上限并接着跑”从检查点继续，已完成的步骤不会重跑。
- 前置记录按文档读取：上游产出和讨论里已有的发言合计超过 2 万字时，成员拿到的是“前置记录目录”，用只读工具按段读取原文，不截断，也不把整段长文塞进每一轮消息。

## Fixed
- 设计器里改了上限，正在跑的运行不受影响，只能新建运行从头再来。
- 预算用完后的续跑、核实后的重试都占用“最多执行几次”，长复核续跑两次就把次数用光。现在同一步从检查点接着跑不再计数，只有返工循环才计数。
- 停机提示改为指向运行页的调整入口，不再要求新建运行。

## Breaking changes
None. 调高只影响本次运行，只能调高，追加记录并写入运行事件；运行快照和流程版本不变。

## Upgrade notes
在设置中检查更新至 2.20.21。已经因为“达到执行次数上限”或用量上限停下的运行，升级后在运行页的上限卡片里调高即可接着跑。以后的运行仍按流程设计器的“总用量上限”（不能超过项目设置里的“每次运行总 tokens”）和成员配置的“每步 tokens 上限”执行。数据目录继续使用 `anyai`。

## Verification
静态检查、类型检查与全部回归测试通过。新增测试覆盖：界面与主进程计算的生效上限一致；存储层只接受针对本次运行对象、高于当前值且不超过最大值的调高，拒绝改写记录；上限卡片识别次数、连线、总量和分段预算，并带入设计里改高的值；续跑不计次数；以及通过本机 HTTP 端到端验证调高上限、重试仍算同一次执行、长上游产出以目录呈现并按段读回原文。未在真实模型上跑完整的长讨论。
