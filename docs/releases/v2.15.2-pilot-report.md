## 四、剩余待解决问题

### R1 · 流程模板重复派活（高）

`生成可编辑协作流程` 产出的 `讨论/决策 → Agent 执行` 两个节点指派**同一个人**，第二个节点把第一个节点做过的事整套重做了一遍：重新声明验收、重新核验、重新列文件。本轮因此多烧约 10 万 tokens（343k 里将近三分之一）。

- **建议**：模板里 `讨论/决策` 节点只在有两位以上成员时生成；单人项目直接 `开始 → 执行 → 结束`。或者让后续节点默认继承前一节点的产出并显式声明"不要重做已完成项"。

### R2 · review 类验收的证据门槛，在协作空间里几乎过不去（高）

`verify_requirements` 对 `review` 类型要求"成功工具步骤的 id/callId 或 `text:` 原文片段"作为证据。但**模型看不到这些 id**——不像 `sourceId` 现在已经写进提示里。本轮模型两次提交都被拒（它的 detail 其实写得很到位：PowerShell 按时间戳列出只有两个文件在本次会话被改过），最后只能标 `unverifiable` 交回人工。

- **建议**：把可引用的证据编号（最近 N 个成功步骤的 callId 与摘要）像 `sourceId` 一样直接列进提示；或者允许引用步骤序号。

### R3 · 预算模型仍是主要摩擦（高）

每轮重发整个上下文，且 `每步预留 = min(成员上限, 剩余总预算)`——越往后每步能拿到的越少。本轮小任务烧掉 343k，中途被切成 3 段，每段都要人工「核实并接着跑」。

- **建议**：三选一或组合——预留额度按"本轮估算"而不是"剩余总量"分配；到达阈值时自动开启下一阶段预算而不是停机等人；把"已完成步骤的产出"折叠进摘要，不要整段重发。

### R4 · 轮次上限把一次小任务切成三段（中）

`本阶段轮次已到` 触发了两次。现在有一键「核实并接着跑」，但仍需人在场。

- **建议**：区分"轮次用完但一切正常"和"需要人核实"——前者可以在预算允许时自动续，后者才停机。

### R5 · 运行详情页缺少总览状态条（中）

`attempt.notice` 已经能显示"在等什么"，但要滚到对应步骤才看得到。页面顶部只有一个 `Running`。

- **建议**：顶部状态条显示"当前节点 / 当前成员 / 在等什么 / 已用 tokens 占预算比例"。

### R6 · 「用户中止」的判定曾经张冠李戴（已在 2.15.2 修）

P2-4 用 `control.stop` 判断是不是人按的暂停，但执行器因预算或轮次自己收尾时也会置这个标志（`onPaused` 里），于是非人为的停机也被写成"用户中止时这一步正在执行"。2.15.2 改用只有 `pause()` 才置位的 `stoppedByUser`。

### R7 · 成员级 failover 仍未在真实故障下验证（中）

本轮给执行者配了接力名单（`openrouter_free · z-ai/glm-5.2:free`），但 sensenova 这次没限流，名单没被触发。2.13.0 的换人逻辑目前只有单元测试覆盖，**没有真实 429 下的实测**。

- **建议**：下次故意用一个没有额度的路由起头，跑一次完整任务验证换人 + 检查点续跑 + `routeLog` 归因。

### R8 ·「运行此版本」默认选中任务列表第一个（中）

从设计器点「运行此版本」，弹窗里的任务默认是列表第一个，不是你正在编辑的那个流程对应的任务。本轮我差点把 PHIL 220 的流程跑到 PSYC 102 的任务上。

- **建议**：默认选中最近一次与该流程关联的任务，或该流程 `freeFlow` 来源的任务。

### R9 · 桌面自动化被置顶窗口挡死时没有任何提示（低，但影响"电脑操作"类功能）

本轮有 20 分钟卡在"屏幕中间一块黑"——omnirouter 配置器置顶压在应用上。对自动化来说这是完全静默的失败。

- **建议**：如果 wickrunAI 以后要做电脑操作，需要"目标窗口被遮挡/不在最前"的显式检测与提示。

### R10 · 免费自动路由的后端质量不可控（低，属于既有约定）

`openrouter/free` 这次分到的后端两次吐出非法工具参数（JSON 截断、工具名里混进 `<｜DSML｜parameter …>`）。应用把它当错误步骤处理了，没崩，loop-guard 也正常拦停——行为是对的，但这类路由**不适合做需要严格工具参数的执行位**。

- 这与"额度按路由各算各的、选择权归用户"的既有约定一致，属于选型建议而非缺陷。
