# 2.11.0 – 2.13.0 — 把协作空间接进已有的那套护栏

单一 Agent 这条路径上做过的三件事——观测回路、完成护栏、失灵即交接——协作空间一件都没接上。这三版把它们接上，顺序是「先能被看见、再能被核验、最后才谈自动换人」。

## 2.11.0 观测与本机完成护栏

**协作运行进观测索引。** 此前 `observeRun` 只接 `RunRecord`，协作运行存在 `collaboration-v1.json` 里，从来没有一条路径进过 `observations`。结果是路由记分、回归集、任务反馈对协作空间完全失明，跑得越多经验层越空。

新增 `team-observations.ts` 做纯投影，三条取舍写死在代码里：

- **来源分开记。** 每条记录带 `source`；`routeScores` 默认只看对话路径，要看协作空间得显式切过去。对话路径的完成背后有 ToolStep 和交付核验，协作空间是流程里的质检节点加人工确认，证据强度不同，混着算就是自欺。
- **只有人工验收算判据。** 质检节点的 JSON 裁决是模型自评，不进判据。算数的只有人在结束节点上点的那一下：批准＝做成，拒绝＝部分做成，失败或取消＝没做成，跑到一半停着＝说不清。
- **用量不按成员拆。** 一次运行只有一个 tokens 合计，多成员时无法归因到某条路由，记成「用量有缺口」而不是造一个精确的假数。

**本机客户端成员的完成护栏。** Claude Code 和 Codex 在它们自己那边执行工具，wickrunAI 一条 ToolStep 都看不到，「已完成」只是一句话。现在这类成员跑完会按隔离区的文件哈希核对一次：该改文件却一个字节没动，或者要求测试与推送而这边根本看不到执行记录，这一步就转成**待核实**交回给人，既不算通过也不算失败。

判断只看这一步的指令和输出要求，**不看整次运行的目标**——否则「顶层设计，不要改文件」这种步骤会被运行目标里的「修改」误判成没干活。

## 2.12.0 成员能用的东西补齐

成员此前拿不到单人对话早就有的四样东西，这版补上：

- **学到的限速与窗口**：成员既读不到也不回写，跟 2.3.15 修好的子代理漏桶是同一个 bug，换了条支路。
- **技能**：成员配置里新增技能勾选。**由用户勾，不按指令自动匹配**——自动塞技能等于替用户改了他没写的要求。正文过长的技能照样只放开头，成员要具体规范时用 `read_skill` 取回。
- **`recall_past_task`**：默认零关联不变，成员显式调用才查，只查同一个项目。
- **项目规范与文档**：成员的 system 前缀里现在有 `projectSystemBlock`，本机客户端那条路径同样带上。项目的约定不该只有对话知道。

## 2.13.0 成员级失灵即交接

成员的路由失灵时按名单交给下一位，检查点带过去，进度不重来。规矩跟单人对话完全一致：**名单是用户排的**，程序不挑不打分；**换不换**由 `errors.ts` 的归类决定，`bad_param` / `loop_detected` / 说不清的错误刻意留在原地；**怎么换**由运行时执行，检查点按成员 id 存着，已发生的副作用由幂等键账本兜住。

两个刻意的边界：

- **成员快照不改写。** 运行创建时固定的成员配置是审计基线，`collaboration-store` 会拒绝任何改写。换人只活在这一次派发里，留痕走新增的 `routeLog` 和运行事件。
- **观测按实际用过的路由分行记。** 没有这份流水，整段成绩会记到接手那条路由头上，被换下来的那条反而干干净净——记分表从此是错的。

名单来源两层：成员自己的名单 > 应用全局名单。不设就是原来的行为，一点不变。本机订阅客户端不参与自动交接：它的失败没有统一的错误归类，拿不准就不换。

## 配置模板可以导入了

导出一直都有，导入没有，于是一套跑通的流程没法在另一台机器或另一个项目重来一遍。现在项目设置里可以导入模板，规矩是：**全部换新编号、导入的成员一律先停用、不带运行记录与经验**。流程版本要在设计器里重新保存一次再运行——版本是「当时跑的是这一份」的证据，换了编号就不是它了。

仓库里附带一份可直接导入的微型试点流程：`docs/templates/readinglog-pilot.json`（顶层设计 → 执行 → 独立质检，质检不通过打回返工，最多两轮）。
