# wickrunAI 4.0.2 — 稳定第三方客户端、视频与大文件输出、云文件库

**卡顿与稳定性**

- 修复接入 Grok、Kimi、Codex 等官方客户端执行长任务时界面卡死：此前每个进度事件都会在主进程同步写盘并立即通知界面，成千上万个事件会让窗口停住。现在进度合并写盘（最多一次写入在途，不再同步落盘），界面事件按 100 毫秒合并，文字和工具状态一个都不丢。压力测试中同步写盘由 3002 次降到 2 次，主进程阻塞由约 10 秒降到约 2 毫秒。
- 关闭或停止对话时结束客户端的整个进程树（Windows 使用 taskkill，其他系统使用进程组），不再留下后台残余进程继续占用内存。
- Grok 连续 15 分钟（可在运行设置里调整）没有任何动态时自动停止等待，保留已有输出和进度，并提示如何继续或重试。
- 另存为大文件改为异步复制，不再阻塞界面。

**视频、音频与大文件输出（不限于某个模型）**

- Grok、Kimi、Codex 等客户端在工作目录里生成的视频、音频、大图和压缩包，会自动出现在“本轮文件与产物”，即使任务中途出错也会列出已经生成的文件。
- 视频和音频直接从本机磁盘流式播放，支持拖动进度条；文件不再整份读入内存，多 GB 的视频与小文件占用相当。不能在窗口内播放的编码（如部分 mkv/avi）会提示用默认程序打开或另存为。
- 普通 API 模型在回复里返回的图片、语音和视频（OpenAI 兼容的 images / 内容分段 / audio、Gemini 内嵌数据、Responses 图片生成、图片生成接口、回复文字里的媒体链接）统一保存为文件。供应商的下载链接会过期，因此立即下载；只接受 https，拒绝指向本机或内网的地址，并限制单个文件 2 GB。
- 桌面端文件卡片新增“上传到云端”：分片直传、断点续传、显示进度。

**云文件库（网页与桌面）**

- 新增“设置 → 云文件”：容量条、在线播放视频/音频/图片、下载、删除；网页端可直接上传文件。文件保存在 Cloudflare R2 私有存储，服务器只保存权限和额度，字节由浏览器或桌面端直传，下载使用短时有效的签名链接，只有上传者本人可读取。
- 默认额度：免费 1 GB，付费 10 GB（单文件最大 5 GB），运营者可通过 MEDIA_FREE_MB、MEDIA_PAID_MB、MEDIA_MAX_FILE_MB 调整。套餐降级或超额后禁止新上传，已有文件保留且仍可下载和播放。未完成的上传 24 小时后自动回收，不再占用额度。
- 新增：共享文件的新上传改存 R2。字节仍由浏览器或桌面端直传，服务器只检查权限、额度和大小；谁能读取仍由共享项目自己的权限（私有、链接、邀请、团队、群组、历史版本）判断，每次下载都先过权限再签发 15 分钟有效的链接，撤销共享后旧链接的请求立刻被拒绝。共享文件上限从 100 MB 提到 5 GB（端到端加密的共享项目因需在设备上整体加解密，仍是 100 MB）；大文件下载直接从签名链接保存，不再整份读入内存。
- 共享文件与云文件库共用同一份额度（免费 1 GB / 付费 10 GB），计入上传者；旧版存在数据库里的共享文件也计入，不会被迁移或破坏，继续可读。上传后一直没被保存到项目里的文件 48 小时后自动回收。
- 需要运营者配置 R2_ACCOUNT_ID、R2_ACCESS_KEY_ID、R2_SECRET_ACCESS_KEY、R2_BUCKET，并在桶上设置允许站点来源的 CORS。未配置时该功能自动关闭并给出提示，其他功能不受影响。

**已知限制**

- 云文件库内容目前不使用端到端加密，服务器运营者可通过存储访问这些文件；需要端到端加密的内容请继续使用加密同步和加密共享。加密视频需要分块加密设计，留待后续版本。
- 个人同步的附件仍沿用 4.0.1 的分块、可续传机制，单个文件（上限 128 MiB）在同步时整体读入内存；更大的视频请使用云文件库。
- 云文件库（设置 → 云文件）本身仍只对上传者本人开放；要与别人共享，请在共享空间里上传。
- 共享文件删除项目或旧版本后，已上传的字节暂不回收，仍计入上传者额度（与此前历史版本占额度的规则一致）；R2 共享文件不做同内容去重，也不在服务端校验内容哈希，只校验字节数，下载端若有哈希则会校验。
- 共享群聊的消息数（1000 条）与单条大小（500 KB）限制本版未改动。
- 本地测试未覆盖真实 Cloudflare R2 与真实 Grok CLI 的端到端运行；上传、签名和播放在模拟存储与协议层测试，发布后需用真实账号做一次验收。
