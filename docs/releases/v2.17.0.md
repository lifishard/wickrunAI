# v2.17.0 · 产物交接、独立复核与可追溯接力

跨成员协作现在可以把未合并的产物发布为不可变版本，并接收到另一位成员的隔离目录。执行与复核模板支持“执行 → 只读复核 → 有限返工 → 用户验收”；复核须引用实际读取证据和本次产物版本，过期或接收后变化的文件不能沿用通过结论。复核用副本不重复提供合并动作。

同时修复成员预算被阶段建议下限抬高的问题，以及只要求修改文件的本机成员被误判为缺少测试证据的问题。任务契约由现有持久记录派生，压缩与跨模型交接保留来源和未知操作；请求注入使用有长度上限的投影，完整原文仍可检索。

产物接收增加中断日志与恢复。普通、最终、压缩请求具有稳定编号，团队统计按编号去重；未知与多路由归因缺口明确保留，不推算货币成本。定时跳过策略也会阻止暂停或结果未知的旧运行与新运行重叠。

## 验证与兼容边界

- 实际 Electron 隔离实例跑通：错误产物 → 复核 fail → 修正 → 新版本复核 pass → 查看差异 → 人工批准 → 合并。证据见 [桌面验收记录](../acceptance/2.17.0/README.md)。模型由本地受控 HTTP 服务提供，不能冒充真实供应商质量证明。
- 自动化覆盖真实 HTTP 429 接力、成功操作不重复、未知副作用停止、接收中断恢复、跨范围拒绝、伪证据与旧版本拒绝、压缩来源和纠正/否定保留、用量去重、记忆停用与项目隔离。
- 质检节点暂只支持提供可见工具证据的 API 成员。历史 `readinglog-pilot.json` 保留当时配置；导入后须把质检席位改为 API，再启用和保存新版本。本机客户端仍可承担执行工作。
- 运行文件副本不等于操作系统沙箱；真实供应商质量/策略收益、多路由精确成本归属、纯文本复核与更完整长任务试验列为后续工作。

工程基线、完成状态与剩余工作见 [PROGRESS](../../PROGRESS.md)、[施工路线图](../ENGINEERING_ROADMAP.md) 和 [验收条件](../NEXT_STAGE_ACCEPTANCE.md)。本次未发布或替换日常安装。
