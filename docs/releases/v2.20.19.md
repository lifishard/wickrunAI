# wickrunAI 2.20.19 — 运行出错时就地换模型继续

团队运行因为某位成员的模型不可用而停下时，运行页会直接指出是哪位成员、哪条接入、为什么不行，并让你就地换一个检测过的模型，再从这一步继续。以前只能填写核实依据后重试，原样重试仍会失败，改模型要离开运行页。

## Added
- 修复卡片：列出出错成员、原接入与模型、上游原文和可行修法；就地选择新的接入和模型。
- 选好模型后发一条很短的测试请求，确认它在套餐内；已验证的模型在列表中标记。新模型不接受原来的思考强度时改为不下发。
- 出错的尝试没有执行任何工具步骤时，一键“换用并重试此步骤”；已有执行记录时只换模型，仍需核实后继续。
- 讨论里还没轮到的成员可以一起检测，未通过的一并换用，避免重试后又停在下一位。
- 默认同时更新项目里的成员设置，以后的运行直接用新模型。提供“配置成员”和“打开接入设置”跳转。

## Fixed
- “model is not available in the current token plan”等“模型不在套餐”回复会按状态码被误判为参数错误（400）或凭据错误（403），修法也跟着给错；现在统一识别为路由问题，修法是换模型，配置了接力名单时也会按名单交接。
- 运行记录保存每位成员出错时的错误归类、状态码和原文，停下后能准确指出是谁出错。
- 兼容性检测未通过时显示上游原文，不再只有状态码。

## Breaking changes
None. 运行开始后成员快照不变；换路由只追加记录并写入运行事件，存储层拒绝改写或删除这些记录，也不允许换成本机客户端。

## Upgrade notes
在设置中检查更新至 2.20.19。已经停在“这一步需要处理后再继续”的旧运行，升级后同样显示修复卡片。限流和网络中断仍自动等待重试；原因不明的错误仍走核实面板。数据目录继续使用 `anyai`。

## Verification
静态检查、类型检查与全部 1048 项回归测试通过。新增测试覆盖：“模型不在套餐”在不同状态码下的归类；从运行记录找出出错成员和还没轮到的成员；有执行记录时要求核实；旧记录兼容；限流、说不清的错误、本机客户端和已处理尝试不提供换用；以及通过本机 HTTP 端到端验证停下、换路由、重试后用新模型完成，存储层拒绝改写换路由记录。界面用服务端渲染检查了未换用和已换用两种状态；未在真实供应商套餐上复现原错误。
