# wickrunAI 2.20.23：阶段预算卡住时指出该调哪一项

一段的预算取“成员每步 tokens 上限”和“本次运行还剩多少”里的小者。原来卡片只让你调成员上限，调到九百多万也没用，因为真正卡住的是本次运行剩下的总量。

## Fixed
- 上限卡片按实际的边界给出修法：本次运行剩下的量比成员上限少，或者不够发一轮时，卡片列出“本次运行总 tokens”并把它作为必须调高的一项；只有成员上限才是边界时，才列出成员上限。
- “剩余阶段预算不足”现在写明这一轮约需多少 tokens、这一段还剩多少，卡片据此给出足够的建议值。
- 下一段仍然放不下这一轮时，不再原样自动续跑三次再停，直接停下来让你调上限。
- 停机说明改为：每段预算取两项里的小者，卡片会标出该调哪一项。

## Changed
- 分段读取长记录时，提示成员在同一轮里一次请求多段。每多一轮都要重发已读的内容，一段一段读更费 token。

## Breaking changes
None.

## Upgrade notes
在设置中检查更新至 2.20.23。已经停在“剩余阶段预算不足”的运行，打开运行页，在卡片里调高“本次运行总 tokens”后点“提高上限并接着跑”。之前调高的成员上限会保留，不影响结果。数据目录继续使用 `anyai`。

## Verification
静态检查、类型检查与全部回归测试通过。新增测试覆盖：成员上限已经很高、剩余总量只有两万出头时，卡片只列出本次运行总量；总量充足时只列成员上限；这一轮比成员上限还大时两项都列；从报错里读出这一轮约需的量，旧记录读不到时按 0 处理。另外在本机用协作记录副本回放了卡在这里的那次运行：卡片给出“本次运行总 tokens 300,000 → 450,000”，调高后复核步骤读完全部分段，进入用户验收。回放使用假模型，未调用真实模型。
