# wickrunAI 2.20.22：停止的运行可以重新打开，接着跑

点了“停止运行”之后，原来只能新建运行从头再跑，已经花掉的 token 要再花一次。现在停止的运行可以重新打开，从停下的地方接着跑，已完成的步骤不会重跑。

## Added
- 重新打开：已停止的运行在运行页显示“重新打开并接着跑”。已完成的步骤、记录、产物和用量都保留；没有卡住的上限就直接继续，有的话先显示上限卡片。停止时还有没核实的操作，会先回到“待核实”，核实后再继续。

## Fixed
- 时间上限按实际执行的时间计算。原来从创建运行起算墙上时间，停了一夜再恢复，一接着跑就撞上“总分钟”上限；现在停下、等你处理和关机的时间都不算。
- 只读的步骤不再因为“目标要求修改”被卡住。运行目标里写了“修复”“生成报告”“直接执行”时，只能读前置记录、交付文字的步骤（包括长文本分段复核）会被判成“只有查阅记录”，反复追问后停下，白花 token。现在这类步骤按文字交付判断；能写文件或执行命令的步骤照旧检查。
- 上限卡片不再推荐比已用量还低的设计值，避免采用后一恢复就再次停下。

## Breaking changes
None. 重新打开会追加一条运行事件；存储层只接受带这条事件的恢复，并且不允许借此跳过对未核实操作的核实。已完成的运行仍不能重新打开。

## Upgrade notes
在设置中检查更新至 2.20.22。之前停止的运行，打开运行详情，点“重新打开并接着跑”。数据目录继续使用 `anyai`。

## Verification
静态检查、类型检查与全部回归测试通过。新增测试覆盖：时间上限只计执行时段（重叠步骤只算一次，中断的步骤算到停下为止）；不推荐已用完的设计值；通过本机 HTTP 端到端验证停止后重新打开、调高上限、接着跑时不重跑已完成步骤，执行中停止的运行重新打开后必须先核实，存储层拒绝绕过；以及运行目标写了“修复”时，只读前置记录的步骤能正常交付。另外在本机用真实的协作记录副本回放了一次停止的运行：重新打开后没有上限拦截，只继续了停下的复核步骤，读完全部分段后进入用户验收。回放使用假模型，未调用真实模型。
