# wickrunAI 2.20.18 — 管家遇到限流自动等待重试

管家现在沿用单一 Agent 的限流策略。遇到 TPM/RPM 超限时，它会排队、等待并自动重试，不再直接显示“没有收到完整方案”，用户也不必等冷却后手动重发。

## Added
- 管家请求与单一 Agent、团队成员共用同一凭据的额度账本。已知 RPM、TPM 或上游剩余额度时先排队再发送，减少撞限。
- 遇到 429 或 TPM/RPM 超限时，记录该路由限额，按 Retry-After 等待；上游没有给出时间就等待 62 秒，然后自动重试。方案格式修正请求同样适用。
- 等待时在回复位置显示倒计时，可随时停止。
- 从响应头和限流报错中学到的限额写入设置，单一 Agent 与团队运行共同使用。

## Fixed
- 管家遇到 `ModelAccountTpmRateLimitExceeded` 等上游限流时直接失败。
- 兼容性检测与正式请求改用同一额度分组；限流后检测请求也会排队，不再抢先发送。
- 单一 Agent 遇到无法解析的 Retry-After 时会立即重试；现在按默认 62 秒等待。

## Breaking changes
None.

## Upgrade notes
在设置中检查更新至 2.20.18。自动重试关闭时，限流直接显示，已填写的需求保留。等待总时长受阶段恢复上限约束，默认 15 分钟；余额不足、认证失败等错误不会重试。上游账户整体额度已满时仍要等待，本版本减少的是无效撞限和手动重发。数据目录继续使用 `anyai`。

## Verification
静态检查、类型检查与全部 1041 项回归测试通过。新增测试覆盖：限流后按 Retry-After 等待并重试、学习限额、共用额度分组、自动重试关闭时直接报错、等待中停止后不再发送、非限流错误不重试，以及共用等待时长规则。上游响应来自受控测试服务，不代表任何供应商的实际限额。
