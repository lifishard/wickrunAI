# wickrunAI 2.20.20 — 长讨论完整复核，协作成员与单一 Agent 同等授权

讨论产出的长文本现在可以完整复核，不再因为超过 2 万字停下。协作空间的成员也能像单一 Agent 一样使用内置浏览器、命令行、改代码、写文件和屏幕控制，需要更多权限时在运行页向你申请。

## Added
- 分段复核：待复核文本超过 2 万字时，复核成员按段读取全部原文（每段约一万字，原样返回），每段都读过才能判通过；发现足以判不通过的缺陷时可以直接判不通过。全程不截断。
- 成员配置新增“屏幕控制”和“权限”两组工具。
- 运行中申请授权：成员可以申请目录外路径、屏幕控制或管理员命令。申请出现在运行页“需要你的确认”，批准后只对本次运行里的这位成员有效，并写入运行记录。
- 文件任务里，成员配置的联网、浏览器、GitHub、项目文档等工具一并开放；文件读写和命令仍按所选的读/改/命令级别限定在任务目录。
- 想法梳理运行开放只读工具（联网搜索、读网页、浏览器读取、读文件、读项目文档）；写文件、命令、申请授权等执行类工具仍不开放。
- 质检步骤可以用只读的联网和浏览器工具核对事实，仍不能修改。

## Fixed
- 讨论或长文产出超过 2 万字后，文本复核直接失败，重试也同样失败，没有可操作的出路。
- 协作成员申请授权时一律被拒（“协作运行权限固定”）。
- 逐项询问模式下，申请授权会先弹一次普通工具确认，再弹一次授权确认；现在只确认一次。

## Breaking changes
None. 已有成员、流程和运行快照不变。想法梳理运行里的成员现在可以带工具，但执行时只开放只读工具。

## Upgrade notes
在设置中检查更新至 2.20.20。之前因“文本产物超过 20000 字符”停下的运行，升级后在核实面板填写依据并点“核实并接着跑”，复核会改用分段读取。授权只在本次运行里有效，下次运行重新申请；主进程执行工具时只认运行记录里你批准过的授权。数据目录继续使用 `anyai`。

## Verification
静态检查、类型检查与全部 1056 项回归测试通过。新增测试覆盖：长文本不截断、分段原样读取、少读一段不能判通过、判不通过不要求读完；界面与主进程的工具清单一致；想法梳理只放行只读工具；文件任务里文件工具仍受级别约束、其他工具放行；授权只来自本成员在本次运行里被批准的记录，存储层拒绝伪造、改写和想法梳理里的授权记录；以及通过本机 HTTP 端到端验证成员中途申请目录授权、在运行页批准、授权写入运行记录后继续完成。未在真实模型上跑长讨论复核，也未在正在运行的桌面应用里点过授权确认。
