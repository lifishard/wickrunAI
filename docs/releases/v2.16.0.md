# v2.16.0 · 协作空间：少停一次，多说一句

上一版（2.15.2）第一次把协作空间跑通了，但那次运行中人工介入了三回，每回都不是真的有东西要核实。这一版针对的就是那三回。

## R1 · 单人项目不再生成讨论节点

`生成可编辑协作流程` 原来固定产出 `讨论/决策 → Agent 执行`，两个节点指派同一个人，第二个把第一个做过的事整套重做：重新声明验收、重新核验、重新列文件。上次实测 343k tokens 里将近三分之一烧在这。

现在只有两位以上启用成员才生成讨论节点；单人直接 `开始 → 执行 → 结束`。逻辑从组件里抽成纯函数 `freeFlowGraph()`，有回归测试。

## R2 · review 类验收拿得到证据编号

`verify_requirements` 对 `review` 类型要求引用「成功工具步骤的 id/callId」，但那些调用发生在上一段上下文里，续跑后模型根本看不到编号，只能猜——上次两次提交都被拒，最后只能标 `unverifiable` 交回人工。

现在检查点里最近 12 个成功步骤的 `callId（工具名）` 直接列进任务提示，跟 `sourceId` 一样明说；没有可引用编号时也写清楚该拿什么当证据。失败的步骤不列。

## R3 · 每段预算有下限，不足时直说该调哪个设置

每轮要重发整段上下文，剩几千 token 连一轮都发不出去：模型刚被叫起来就报「剩余阶段预算不足」，而这次唤起本身又花掉一轮的钱。

现在一段至少要拿到 `stageFloor(总预算)` —— 绝对下限 20,000 tokens，小预算流程按总预算的两成缩放（10k 的流程不会因为下限一次都跑不起来）。开不了一段时的报错直接写明还剩多少、上限多少、已用多少、至少要多少、该提高哪个设置。

## R4 · 轮次用完且没东西要核实时自动续跑

「轮次用完」和「需要人核实」原来混成同一个停机。现在三个条件同时成立才自动续：停机原因是轮次或阶段预算、没有未确认的工具调用（有副作用风险的一律交给人）、剩余预算还够开一段且节点还有执行次数。同一步最多自动续 3 次，再多就是原地打转，仍然叫人。

顺带修了一个会挂住运行的隐患：`onPaused` 会置 `control.stop`，自动续跑时不清掉的话节点排回队列却没人来跑，运行停在 `running` 上不动。

## R5 · 运行页顶部总览条

原来页面顶部只有一个「运行中」，在等什么、卡在哪一步、谁在跑、预算烧到哪，全要滚到对应尝试里才看得见。现在顶部一条 `runOverview()`：当前步骤 / 执行成员 / 在等什么（批工具、核实、验收三种情况分开）/ 已用 tokens 占预算比例。

## R8 ·「运行此版本」默认选中相关任务

从设计器点运行，任务默认是列表第一个——上次差点把 PHIL 220 的流程跑到 PSYC 102 的任务上，而运行一旦创建，任务和版本就固定了。现在顺序是：这个流程绑定的任务（新的优先）→ 这个流程最近一次运行的任务 → 才轮到第一个；选中的任务平时用别的流程时，运行前检查里会明确提示。

## 另外

- 「达到执行次数上限」的停机补了处理指引（去设计器调高该节点的次数，保存新版本后新建运行）。
- 新增 18 项回归测试，全量 574 项通过。
