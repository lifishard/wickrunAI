# 协作空间易用性支线

用户在 2026-09-20 明确选择：**任务优先，提供可展开的高级设置**。目标同时包含降低首次使用难度和提高可定制性；只隐藏按钮不算完成。

## 已观察的问题

- 首次运行原先要求用户先配置成员、生成流程、进入设计器保存版本，再回到任务启动。
- 任务页并列三个生成按钮、流程选择、运行前检查；按钮讲实现方式，用户仍需自行决定先点哪个。
- 成员、工作流、节点、版本等概念先于任务出现，而“谁执行、谁检查、用哪个模型、能操作什么”分散在不同页面。
- 限流有实际等待机制，但配额错误分类会让部分请求提前停下；失败记录需要区分自动等待、人工暂停和不可重试。

## 第一批 U1：文本任务快速准备（2.17.4）

保留现有界面风格和执行器，在任务页提供模型接入、模型和工作方式。三种方式为直接完成、讨论后完成、完成后复核；默认直接完成，并明确说明额外模型调用。

准备操作创建普通成员、可编辑工作流和固定版本，下一步展示运行前确认；准备本身不发模型请求。新成员只处理文本、关闭自动接力、预算收敛到项目上限。原有成员、流程、目录、权限和历史运行不改写。已有流程仍走原入口；文件流程、成员配置和已有流程选择收进可展开的高级设置。

验收条件：

- 已配置 API 的空项目，无需访问成员页或设计器即可启动文本任务。
- 从保存任务到派发只需“准备并检查”和“确认范围并开始”；省略的是手工配置，不省略运行确认。
- 准备后有 1/2 位成员、1 份流程和 1 个固定版本，运行数与请求数仍为 0。
- 三种方式分别生成正确结构；所有结构保留人工交付门槛；旧团队和预算/允许接入规则不被绕过。
- 高级入口可找到原有能力，生成的流程仍可修改；不能成为不可定制的黑盒。
- 关闭自动重试时如实提示；开启时说明默认 62 秒及 Retry-After 优先，不把所有 429 视为永久额度不足。

工程与桌面证据集中在 `docs/acceptance/2.17.4/`。本批只覆盖文本快速入口，不宣称已经完成文件任务、混合客户端或完整学习成本评估。

## 后续施工顺序

| 项目 | 具体工作 | 验收出口 |
|---|---|---|
| U2 · 可直接理解的定制 | 在任务页分别选择执行/讨论/复核模型，编辑角色职责；可选择已有成员，避免每次重复配置；提供团队预设保存/复制 | 调整一位成员不必学习节点；运行前能看到角色→模型→权限映射；旧运行冻结配置保持不变 |
| U3 · 文件任务首跑 | 在任务页选择工作目录和所需能力，提供文件任务的准备路径；明确读取、修改、命令的区别 | 首次文件任务不必跨页找目录/工具；能力与实际派发一致，修改仍在隔离区，未授权能力不可执行 |
| U4 · 运行页与恢复 | 优先展示任务进度、当前等待原因和下一步行动；节点图、调用编号及调试细节按需展开；区分等待重试、待回答、待批准、待核实 | 不看流程图也能判断为何停住；暂停可用；恢复不会重复已成功的副作用 |
| U5 · 导航与新手验证 | 收敛默认导航，统一成员/流程术语；改善表单说明、草稿恢复和连接缺失时的下一步 | 请首次使用者独立完成文本、文件、复核三类任务，记录完成率、求助次数、误操作和时间，再与原入口比较 |

U2/U3 提升定制的可发现性与复用，U4/U5 降低理解运行状态的成本。主线的真实模型质量、恢复与证据工作继续保留；本支线不以界面简化替代其验收。
