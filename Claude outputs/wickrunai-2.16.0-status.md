## 一、这轮改了什么

| 编号 | 问题（来自上一轮实测） | 改法 | 覆盖测试 |
|---|---|---|---|
| **R1** | 一键生成的流程里 `讨论/决策 → Agent 执行` 指派同一个人，第二个节点把第一个做过的事整套重做，343k tokens 里近三分之一烧在这 | 只有两位以上启用成员才生成讨论节点；单人直接 `开始 → 执行 → 结束`。逻辑从组件抽成纯函数 `freeFlowGraph()` | 4 项：单人 3 节点无讨论 / 两人才有讨论且全员参与 / 停用成员不算数 / 任务负责人优先且失效时退回 |
| **R2** | `verify_requirements` 的 review 类型要求引用成功步骤的 callId，但续跑后模型看不到这些编号，只能猜——上轮两次提交都被拒 | 把检查点里最近 12 个**成功**步骤的 `callId（工具名）` 直接列进任务提示；没有可引用编号时也写清该拿什么当证据 | 1 项：续跑提示含成功步骤编号、不含失败步骤 |
| **R3** | 每步预留 = min(成员上限, 剩余总量)，越往后越少；剩几千 token 连一轮都发不出去，唤起本身又花一轮的钱 | 每段预算下限 `stageFloor(总预算)`：绝对下限 20,000，小预算流程按总预算两成缩放；开不了一段时报错直接写明剩多少 / 上限 / 已用 / 至少要多少 / 该调哪个设置 | 2 项：不足时不派发且文案含具体数字 / 小预算按比例缩放不至于跑不起来 |
| **R4** | 「轮次用完」和「需要人核实」混成同一个停机，一次小任务被切三段，三次都不是真的有东西要核实 | 三个条件同时成立才自动续跑：停机原因是轮次或阶段预算、没有未确认的工具调用、剩余预算够开一段且节点还有执行次数。同一步最多 3 次 | 4 项：自动续跑不用人介入 / 有 uncertainCallId 时不自动续 / 到上限后仍交回人 / 用户按的暂停绝不自动续 |
| **R5** | 运行详情页顶部只有一个「运行中」，在等什么要滚到对应尝试里才看得见 | 顶部总览条 `runOverview()`：当前步骤 / 执行成员 / 在等什么（批工具、核实、验收三种分开）/ 已用占预算比例 | 4 项：四项信息 / 三种等待分开 / 讨论节点列全部参与者且已核实的不抢占当前 / 预算为 0 不除零 |
| **R8** | 从设计器点「运行此版本」默认选任务列表第一个，上轮差点把 PHIL 220 的流程跑到 PSYC 102 的任务上 | `taskForFlow()`：这个流程绑定的任务（新的优先）→ 这个流程最近一次运行的任务 → 才轮到第一个；选中任务平时用别的流程时，运行前检查里明确提示 | 2 项：优先绑定任务且取新的 / 退回最近运行的任务且不选已删除的 |

### 顺带修的两处

- **会挂住运行的隐患**：`onPaused` 会置 `control.stop`，R4 自动续跑时不清掉的话，节点排回队列却没人来跑，运行会停在 `running` 上不动。已在 `autoContinue()` 里显式复位。
- **「达到执行次数上限」补了处理指引**：原来只报一句，现在告诉你去设计器调高该节点的次数、保存新版本后新建运行，已完成的产物保留在「文件与产物」。

## 二、R9 更正（你指出的）

上一份报告把那 20 分钟的静默卡死记成了「omnirouter 配置器置顶」。**实际是发起这次自动化的 Claude 桌面端窗口本身压在了 wickrunAI 上面。**

这条比原来那条更要紧：遮挡源不是第三方弹窗，而是**操作发起方自己**——"把别的窗口关掉"解决不了。截图里那块区域被遮住，点击落到了另一个窗口上，没有任何一层报错。

- **修正后的建议**：如果 wickrunAI 以后要做电脑操作，每次动作前先做一次「目标窗口是否前台 + 目标点是否属于目标窗口」的命中测试；不通过就先激活窗口并重新取坐标，仍不通过则明确报错，而不是照着旧截图盲点。
- 已同步改进 `docs/releases/v2.15.2-pilot-report.md` 的 R9 段落。

## 四、下一步：需要你做一件事

我改的是源码，而你机上跑的是已安装的打包版（`AppData\Local\Programs\AnyAI\wickrunAI`），它装的是旧的 `dist`。所以 2.16.0 现在还没生效。

请在仓库目录执行其一：

```powershell
# 快的：只重新构建并打包
npm run dist:win:fast

# 或者开发模式直接跑（不用安装）
npm run dev:electron
```

完成后告诉我，我就用同一个 `reading_log` 小任务重跑一次，目标是**从开始运行到验收门之间零人工介入**——具体要验的是：

1. 一键生成的流程只有三个节点，没有重复派活（R1）
2. 中途轮次用完时自己续跑，不再要我填核实依据（R4）
3. 顶部状态条能直接看出在等什么（R5）
4. review 类验收这次能引用到 callId 而不是标 `unverifiable`（R2）
5. 全程 tokens 明显低于上轮的 343k（R1 + R3 的合并效果）

（我这边的 Linux 工作区跑不了 `npm run build`：仓库 `node_modules` 里的 esbuild 是 Windows 的二进制。测试和类型检查不受影响，都已经跑过了。）
